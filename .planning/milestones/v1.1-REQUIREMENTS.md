## v1.0 Requirements

### Token Optimization

- [x] **TOK-01**: Step 4c in `review-translations.md` uses silent accumulation — AI review findings are written directly to the report file without being output to the conversation context window
  - **Outcome:** Validated in Phase 01. `ai_findings` named variable accumulates to report file; 5,000–30,000 tokens eliminated per run.

- [x] **TOK-02**: `structural_validator.py` accepts a `--summary` flag that outputs only market names and issue counts (not full JSON arrays), reducing context load during triage
  - **Outcome:** Validated in Phase 01 (flag built), realized in Phase 07 (flag wired into Step 2 call site). 80-90% token reduction from structural validator output.

- [x] **TOK-03**: Token usage before and after optimization is measurable — a baseline metric exists to validate the improvement
  - **Outcome:** Validated in Phase 01. `reports/token-baseline.md` created before optimization.

### Reference Document Reliability

- [x] **REF-01**: The review skill explicitly logs which reference files were loaded and their version/row count at the start of each review
  - **Outcome:** Validated in Phase 02. Step 1 health check logs name, row count, and load status for all 3 config files.

- [x] **REF-02**: Variable validation against `Variables.csv` produces an explicit pass/fail per market — unknown variables always flagged
  - **Outcome:** Validated in Phase 02. `load_valid_variables()` returns None on missing file → hard abort before validation.

- [x] **REF-03**: Formality rules from `tone_guidelines.json` are applied to every market's AI review — report flags formality deviations
  - **Outcome:** Validated in Phase 02. Step 4c criterion 2 reads `formality_rules.*` and emits Warning finding on deviation.

### Report Format

- [x] **RPT-01**: Report output format is configurable — user can choose `.md` or PDF without editing source code
  - **Outcome:** Validated in Phase 02. `--format md|pdf` flag (HTML removed in Phase 5).

- [x] **RPT-02**: Report structure is consistent across runs — same sections in the same order regardless of which markets are flagged
  - **Outcome:** Validated in Phase 02. Sections 1/2/5 always present; 3/4/6 conditional on findings.

- [x] **RPT-03**: Markdown output is generated by default. Superseded by NTIO-04: HTML removed in Phase 5; .md is now the sole default format.
  - **Outcome:** Validated in Phase 02 (HTML default), superseded in Phase 05 (.md default), prose updated in Phase 07.

### Feedback Loop

- [x] **FBK-01**: `corrections_log.json` schema is structured with explicit 8 fields: `language`, `notification_type`, `issue_category`, `original`, `corrected`, `rule_extracted`, `confidence`, `date`
  - **Outcome:** Validated in Phase 03. Schema enforced in all write paths.

- [x] **FBK-02**: Step 7 feedback workflow extracts structured rules and appends them with the above schema (not freeform text)
  - **Outcome:** Validated in Phase 03. Step 7b writes 8-field entries; batch path uses `notification_type=batch-feedback`.

- [x] **FBK-03**: A `rules_summary.json` export is generated after each feedback session — flat list of extracted rules by language
  - **Outcome:** Validated in Phase 03. Step 7d rebuilds rules_summary.json from scratch after every session; batch path rebuilds once after all writes.

- [x] **FBK-04**: The review skill loads and surfaces the top 3 most relevant past rules per language at the start of each AI review
  - **Outcome:** Validated in Phase 03. Step 3 scores rules by `occurrence_count × recency_weight × confidence_score`, injects top-3 into Step 4c criterion 7.

### Team Handoff — DEFERRED

- [ ] **HND-01**: `README.md` exists at the project root with: prerequisites, setup steps, how to run a review, how to read a report, how to submit feedback
  - **Outcome:** Deferred. Juan runs the tool throughout v1.1; deferred to v1.2 or standalone.

- [ ] **HND-02**: `requirements.txt` exists for optional PDF/HTML dependencies
  - **Outcome:** Deferred alongside HND-01.

- [ ] **HND-03**: The `generate_pdf.py` script accepts `--input` and `--output` CLI arguments
  - **Outcome:** Deferred. HTML removed, PDF less relevant.

## v1.1 Requirements

### Notion Publishing

- [x] **NTIO-01**: Report is automatically published to Notion upon completion — no extra command or user confirmation required
  - **Outcome:** Validated in Phase 05. Notion publish block in Step 6 via `mcp__claude_ai_Notion__notion-create-pages`.

- [x] **NTIO-02**: The Notion page mirrors the .md report structure — all markets, same section order, same content
  - **Outcome:** Validated in Phase 05. Step 6b adapts .md content (table conversion, variable escaping) before Notion call.

- [x] **NTIO-03**: Notion page title includes the notification ID and review date
  - **Outcome:** Validated in Phase 05. Title format: `Translation Review — [notification_id] — [YYYY-MM-DD]`.

- [x] **NTIO-04**: HTML output format is removed; .md file is retained on disk as local backup
  - **Outcome:** Validated in Phase 05. `--format` accepts only `md|pdf`; `md` is default; HTML removed from all 5 locations.

### Batch Feedback Routing

- [x] **FBK-05**: User can submit a batch of feedback comments in one go (not one-by-one)
  - **Outcome:** Validated in Phase 06. Language+Issue block format triggers 7a-batch branch automatically.

- [x] **FBK-06**: For each comment in the batch, the system analyzes and suggests a routing action with brief rationale and conflict flag
  - **Outcome:** Validated in Phase 06. 4-bucket routing (corrections_log.json, label_patterns.json, tone_guidelines.json, Variables.csv flag-only) with per-item block list display.

- [x] **FBK-07**: User confirms or rejects each suggestion; confirmed actions are applied to the correct file immediately
  - **Outcome:** Validated in Phase 06. Number-based confirmation, one-pass write, single 7d rebuild, change summary.
