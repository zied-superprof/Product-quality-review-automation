# Milestone v1.1: Notion Publishing & Batch Feedback Routing

**Status:** ✅ SHIPPED 2026-04-14
**Phases:** 1–3 (v1.0 carried forward), 5–7 (v1.1 new)
**Total Plans:** 11

## Overview

Two natural delivery boundaries: first, connect report output to the team's Notion workspace and remove the now-redundant HTML format; second, replace the one-at-a-time feedback loop with a batch routing system that suggests which config file each correction belongs in. Both phases build on the structured feedback loop from v1.0 Phase 3. Phase 7 closed integration and documentation gaps surfaced by the v1.1 milestone audit.

## Milestone Summary

**Key Decisions:**
- HTML output removed entirely (NTIO-04); .md is the sole default; Notion page is the shareable output
- Notion publish via `mcp__claude_ai_Notion__notion-create-pages` inside the skill — no separate script
- Batch feedback routing extends Step 7 — Language+Issue format triggers batch branch; #N format preserves single-item flow
- Variables.csv routing is always flag-only — never written, never in confirmation set
- `--type` flag removed from structural_validator.py call (was planned but never implemented in script)

**Issues Resolved:**
- TOK-02 token savings realized: `--summary` wired into Step 2 call site (Phase 7)
- RPT-03 prose stale (referred to HTML default): updated to `.md` default (Phase 7)
- Stale plan-06-02 implementation comment removed (Phase 7)
- FINDING-01: `--type` argparse crash on every review run — fixed 2026-04-14

**Issues Deferred:**
- HND-01/02/03: README, requirements.txt, generate_pdf.py CLI args — deferred to v1.2
- Live verification of Notion MCP execution, conflict detection semantic quality, relevance scoring accuracy

**Technical Debt at Close:**
- 14 human-verification items (all require live runs; none block goal achievement)
- SUMMARY.md files missing `requirements-completed` YAML frontmatter (documentation pattern gap only)
- Step 1 health check references abbreviated tone_guidelines.json path (low severity, AI finds data anyway)
