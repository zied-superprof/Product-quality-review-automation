  <action>
Perform four contradiction scans and append results to `08-01-raw-findings.md` under section `## Contradictions`.

**Scan 1 — Internal corrections_log.json contradictions (per D-09):**
Parse `corrections_log.json`. For each language, collect all entries. Flag any pair where the same language has conflicting guidance (e.g., one entry says "use formal" and another says "use informal" for the same market). Compare `rule` and `correction` fields for semantic conflicts.

**Scan 2 — Corrections vs config cross-check (per D-10):**
For each entry in `corrections_log.json`, check whether its rule contradicts an established standard in `tone_guidelines.json` (formality rules, `formal_vous_languages`, `informal_standard_languages`) or `label_patterns.json` (`subject_variable_usage_rules`). Example contradiction: a correction rule says "use informal tú" for a language listed in `formal_vous_languages`.

**Scan 3 — Doc-vs-implementation mismatches (per D-11):**
Compare what CLAUDE.md and `.claude/commands/review-translations.md` say the tool does against what `structural_validator.py` actually implements. Specific checks:
- Does the skill definition reference any CLI flags that `structural_validator.py` argparse does not accept? (Reference: the `--type` flag incident was already fixed, but check for others.)
- Does CLAUDE.md describe checks that `structural_validator.py` does not actually perform?
- Does the skill definition describe steps that produce outputs in a format different from what the scripts actually output?

**Scan 4 — Skill definition vs structural_validator.py behavior (per D-12):**
Read the skill definition's description of what structural validation checks for (variable preservation, HTML structure, empty fields, etc.). Read `structural_validator.py` to confirm each described check has corresponding code. Flag any check described in the skill but not implemented, or implemented but not described.

**Also check (per D-07):** Whether `rules_summary.json` is in sync with `corrections_log.json` — does `rules_summary.json` reflect the current state of corrections_log, or has it drifted?

**Output format:** Each contradiction finding gets:
- Finding number `[#N]` (continuing from Task 1's numbering)
- Contradiction type: `internal-conflict` | `config-mismatch` | `doc-vs-implementation` | `sync-drift`
- Files involved
- Specific conflict description with quoted evidence
- Severity suggestion (critical if it causes wrong review output, medium if misleading, low if cosmetic)
  </action>
