## Summary

Phase 2 spans two areas: (1) hardening Python config-file loading in `structural_validator.py` and enforcing formality checks in the AI review skill, and (2) upgrading report output so HTML is the default and section structure is locked. All required infrastructure already exists — no new libraries are needed beyond the `markdown` package already used in `generate_pdf.py`.

The two Python changes are surgical: `load_valid_variables()` must return `None` (not `{}`) when the file is missing, and its caller in `run_validation()` must treat `None` as a hard abort rather than silently proceeding. The `check_variables_catalogue()` guard `if not valid_variables: return []` at line 228 must be removed or conditioned so it fires only when the file was intentionally empty, not when it failed to load. The formality-deviation check lives entirely in the AI review skill (Step 4c criteria), not in Python code.

The HTML-default change is straightforward: after Step 6 writes `review-[id]-[date].md`, the skill runs the MD→HTML conversion inline using `markdown.markdown()` plus the CSS template extracted from `generate_pdf.py`. Both files are always written; PDF is skipped unless `--format pdf` is passed. The notification ID for the filename is extracted from CSV content during Step 1 parsing, with a defined fallback strategy when multiple notifications exist.

**Primary recommendation:** Implement changes in two sequential plans: (1) Python config-file hardening + formality AI criteria, (2) report format/naming/HTML output — matching the ROADMAP plan split exactly.

### Pattern 1: Hard-fail on missing required config file
**What:** `load_valid_variables()` returns `None` when Variables.csv is absent; `run_validation()` detects `None`, prints an abort message to stderr, and calls `sys.exit(1)`. Review skill Step 2 checks the exit code and aborts before Step 3.
**When to use:** Any required config file (Variables.csv, tone_guidelines.json, label_patterns.json).

```python
# In load_valid_variables():

    path = Path(config_dir) / 'Variables.csv'
    if not path.exists():
        return None          # Caller must treat as fatal
    # ... existing loading logic ...
    return valid

# In run_validation():
valid_variables = load_valid_variables(config_dir)
if valid_variables is None:
    print("ABORT: Variables.csv not found in config/. Cannot proceed.", file=sys.stderr)
    sys.exit(1)
```

### Pattern 5: MD→HTML conversion inline in skill
**What:** After Step 6 writes `review-[id]-[date].md`, the skill runs an inline Python snippet to convert Markdown to HTML using the CSS template from `generate_pdf.py`.

### Pattern 6: Notification ID extraction from CSV content
**What:** The notification ID drives the report filename (D-19 to D-21). It must come from CSV content, not filename.
**Discovery strategy (for Claude's discretion implementation):**
1. Look for a column named "notification", "notification_id", "id", or similar in the CSV header row.
2. If not found, use the CSV filename (without `.csv` extension) as a fallback.
3. For full-database CSVs with multiple notifications: use the first notification ID, or if `--notification` filter is active, use that ID.
4. Sanitize the ID for filenames: lowercase, replace spaces/slashes with hyphens, strip special characters.

Current report filename in existing reports: `review-by-country-reco-val-prof-bo-2026-04-08.md` — the notification ID (`reco-val-prof-bo`) came from the CSV filename `reco-val-prof-bo.csv`. The new naming drops the "by-country-" infix: `review-reco-val-prof-bo-2026-04-08.md`.

### Anti-Patterns to Avoid
- **Returning empty dict on missing file:** `load_valid_variables()` currently returns `{}` on missing file — this silently bypasses all catalog checks. Must return `None` to force caller abort.
- **Hardcoding paths in generate_pdf.py reuse:** Phase 4 will add `--input`/`--output` CLI args to generate_pdf.py. Phase 2 must not call generate_pdf.py as a subprocess with hardcoded paths, or Phase 4 becomes a breaking change.
- **Over-counting language entries:** tone_guidelines.json has three lists (formal_vous_languages, informal_standard_languages, neutral_languages). The log line count should reflect the total number of distinct language codes, not just one list.
- **Changing report section order at runtime:** Section order is fixed per D-18. Do not conditionally reorder sections based on which markets have issues.

## Common Pitfalls

### Pitfall 1: load_valid_variables returns {} silently on missing file
**What goes wrong:** Current `load_valid_variables()` at line 174 returns `{}` when Variables.csv is absent. `check_variables_catalogue()` at line 228 guards `if not valid_variables: return []` — meaning all catalog checks are skipped silently.
**Why it happens:** Defensive coding pattern without an explicit abort path.
**How to avoid:** Change return type to `dict | None`. Return `None` on file-not-found. Caller in `run_validation()` calls `sys.exit(1)` on `None`.
**Warning signs:** Running validation with a missing Variables.csv produces zero `variable_undefined` findings — should be impossible if any `@TPL_*@` variable is present.

### Pitfall 2: generate_pdf.py has hardcoded paths
**What goes wrong:** `generate_pdf.py` at lines 7–9 hardcodes `review-by-country-2026-04-03` as filename. Calling it as a subprocess in Phase 2 would require either editing those lines or complex argument passing — conflicting with Phase 4's planned `--input`/`--output` args.
**Why it happens:** The script was written for one-off use.
**How to avoid:** Implement MD→HTML conversion inline in the skill (Pattern 5), copying only the CSS template from generate_pdf.py. Do not call generate_pdf.py as a subprocess in Phase 2.

### Pitfall 3: Report filename collision when MD and HTML are always written
**What goes wrong:** Both `review-[id]-[date].md` and `review-[id]-[date].html` are written every run. If a user runs the skill twice on the same day with the same CSV, the second run silently overwrites both files.
**Why it happens:** No version suffix or increment logic.
**How to avoid:** Overwrite is acceptable behavior (it's idempotent for the same input). Document this in the skill. No mitigation needed — the MD file is the diff-able source of truth, and HTML is derived.

### Pitfall 4: Formality check fires on informal_standard_languages
**What goes wrong:** Step 4c criterion 2 currently says "formal address where the language has this distinction" — this is ambiguous. Languages like `de`, `it`, `nl`, `ru` are in `informal_standard_languages` but have formal address forms. Flagging them as formality deviations would be incorrect.
**Why it happens:** tone_guidelines.json was updated after the review skill was written; the skill's criterion 2 wording predates the confirmed informal-standard list.
**How to avoid:** Step 4c must explicitly check `informal_standard_languages` list before flagging. Only flag when: language is in `formal_vous_languages` AND informal form is detected.

### Pitfall 5: Undefined variable section appears for French-reference variables
**What goes wrong:** `check_variables_catalogue()` currently runs on ALL entries, including the French reference itself. If France has a legitimate `@TPL_*@` variable not yet in Variables.csv, it would appear in the "Undefined variables" section alongside translation variables.
**Why it happens:** The French reference entry is included in `other_entries` iteration... actually France is passed as `ref_entry` and `other_entries = entries[1:]`, so France is NOT iterated. This is only a risk if the validator is run with a different reference row.
**How to avoid:** No change needed — the existing structure correctly excludes France from catalog checks. Verify this holds when adding the abort-on-missing change.

### Pitfall 6: Notification ID extraction edge cases
**What goes wrong:** Multiple notifications in a full-database CSV. No notification-ID column. Special characters in notification name.
**How to avoid:** Per Claude's discretion, implement the strategy in Pattern 6: prefer content-based extraction, fall back to sanitized filename. When `--notification` filter is active, use that as the ID.

def load_valid_variables(config_dir: str) -> dict[str, str]:
    path = Path(config_dir) / 'Variables.csv'
    if not path.exists():
        return {}           # BUG: silent empty dict, not None
    valid: dict[str, str] = {}

        next(reader)        # skip header
        for row in reader:
            if row and row[0].startswith('@TPL_'):
