# Phase 2: Reference Reliability + Report Format - Context

**Gathered:** 2026-04-08
**Status:** Ready for planning

<domain>
## Phase Boundary

Harden config file usage so the review skill verifiably loads its reference files on every run. Enforce variable catalog checks so unknown variables are always surfaced (never silent). Ship configurable HTML-default reports that non-technical teammates can open in any browser. Report structure must be consistent across runs.

This phase does NOT include: feedback loop restructuring (Phase 3), README / team handoff (Phase 4), or translation generation tools.

</domain>

<decisions>
## Implementation Decisions

### Reference file loading log (REF-01)
- **D-01:** Log appended to the existing Step 1 output line — no separate step, no extra noise
- **D-02:** Format: `Reference files: Variables.csv (788 vars) ✓ | tone_guidelines.json (47 languages) ✓ | label_patterns.json ✓`
- **D-03:** JSON configs (tone_guidelines.json, label_patterns.json) show number of language entries, not file size
- **D-04:** If any reference file fails to load → abort the review immediately with a clear error message before Step 2 runs

### Variable catalog enforcement (REF-02)
- **D-05:** If Variables.csv is absent → abort review (consistent with D-04)
- **D-06:** Unknown `@TPL_*@` variables → always flagged as **Warning** (not Error, not silent) — goal is to grow the catalog through human validation
- **D-07:** "Undefined variables" section at the bottom of the report → shown only when unknown variables were found; absent section = all variables recognized
- **D-08:** All unknown variables are flagged regardless of how many markets show them — the finding prompts human to add to Variables.csv or confirm deprecated

### Formality deviation flagging (REF-03)
- **D-09:** Formality deviations appear as Warning in the per-market AI findings section — no separate report section
- **D-10:** Deviations are flagged when a market's formality doesn't match its configured standard in tone_guidelines.json

### Report output format (RPT-01, RPT-03)
- **D-11:** HTML is the default output format — no flag needed for standard usage
- **D-12:** Format selectable at run time: `--format html|md|pdf` — no source code editing required
- **D-13:** Both `.md` and `.html` are always written — MD is the diff-able source of truth, HTML is for sharing/reading
- **D-14:** HTML generation: Step 6 writes Markdown, then a conversion step produces HTML using the existing styled template from generate_pdf.py
- **D-15:** PDF requires explicit `--format pdf` — not generated by default (requires optional weasyprint dependency)

### Report section consistency (RPT-02)
- **D-16:** French reference section is always present in every report, even when the reference is clean — shows verbatim French title + body
- **D-17:** When a section is empty (no issues of its type), show: `[Section header]\nNo issues found.`
- **D-18:** Section order is fixed: Summary table → French reference → Grouped sections → Single-market sections → Markets with no issues → Undefined variables (if any)

### Report file naming
- **D-19:** Filename format: `review-[notification-id]-[YYYY-MM-DD].[ext]`
- **D-20:** Example: `review-reco-val-prof-bo-2026-04-08.html` and `review-reco-val-prof-bo-2026-04-08.md`
- **D-21:** Notification ID is extracted from the CSV content (not from the CSV filename)

### Claude's Discretion
- Exact wording of abort error messages
- How to extract notification ID when multiple notifications exist in a single CSV
- Implementation of the MD→HTML conversion step (inline in skill vs. calling generate_pdf.py as subprocess)

</decisions>

<specifics>
## Specific Ideas

- Reference file log should feel like a one-liner health check — not a verbose dump
- "The report should tell you what you're looking at" — filename should identify the notification, not just the date
- Unknown variable flagging serves double duty: catches typos AND grows the Variables.csv catalog — make the finding actionable (suggest the human adds it)

</specifics>
