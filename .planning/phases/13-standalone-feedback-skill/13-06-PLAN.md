## Step 11: Tier 2→3 advisory phase (FEEDBACK-10)

After Step 10 promotion, scan Tier 1 + Tier 2 rules for mechanically-checkable patterns that could be promoted to Tier 3 (a check inside `scripts/structural_validator.py`). **The skill is advisory-only — it NEVER edits `scripts/structural_validator.py` (D-11 absolute, FEEDBACK-10 explicit). Tier 2→3 promotion is a human architectural decision (Phase-11 pattern).**

### 11.1 — Detect candidates

For each rule in `corrections/rules_summary.json` > `rules` AND each entry in `config/label_patterns.json` > `subject_variable_usage_rules` (Tier 2 rules), evaluate:

1. **Mechanically checkable** — does the rule describe a pattern that a Python script could verify deterministically? Examples:
   - Regex / character-set check (e.g. "no leading semicolon in style attribute")
   - Structural placement (e.g. "variable X must appear inside block Y")
   - Token presence/absence (e.g. "translation must contain @TPL_NAME@")
   - Counted entity (e.g. "exactly one @TPL_MATIERE_*@ per title")

2. **False-negative history** — does `corrections/corrections_log.json` contain >= 2 entries where the user added this rule retroactively (i.e. AI reviewer missed it and the user supplied the correction)? Heuristic: rules whose `corrected` field describes a structural fact (`empty translation`, `wrong variable for language`, `broken HTML tag`, `malformed CSS`) and whose `confidence` is `high` are typical Tier 3 candidates.

3. **Not already covered** — the suggested check must not duplicate an existing function in `scripts/structural_validator.py`. Quick inspection: search the validator file for keywords from the rule (variable name, character pattern); if a function already addresses the same case, skip.

If zero candidates: output `Tier 3 advisory: no new validator-check candidates this session.` and proceed to Step 12.
