````
## Step 9: Pruning phase (FEEDBACK-06, FEEDBACK-07)

After Step 7 rebuild, scan the freshly-rebuilt `corrections/rules_summary.json` for prune candidates. **This phase runs every session — even sessions with no writes (per CONTEXT.md "Session order" + "Empty-session lifecycle" — pruning is independent of new writes).**

### 9.1 — Detect candidates

Compute today's date (UTC). For each rule in `rules_summary.json` > `rules`, check if it matches AT LEAST ONE of these four gates:

1. **stale** — `today - last_seen > 30 days`
2. **single_occurrence** — `occurrence_count == 1`
3. **low_confidence** — `confidence == "low"`
4. **superseded** — another rule in the same array has the same `language` AND same `issue_category` AND a newer `last_seen` AND a non-contradictory `rule` text (i.e. the newer rule is a restatement/refinement, not a contradiction). Use semantic-similarity judgment, the same lens as the rebuild dedup in Step 7.

A rule may match multiple gates — record all matched gates as the `reasons` array for that candidate. The dominant reason (used in the archive entry) is the first match in this priority order: `superseded > low_confidence > single_occurrence > stale`.

If zero candidates: output `Pruning: no candidates this session.` and proceed to Step 10 (or session end if Plans 13-05/13-06 not yet merged).

### 9.2 — One-by-one review (FEEDBACK-07)

Present candidates one at a time. For each:

```
Pruning candidate (#N of M):
  Rule: "[rule text]"
  Language: [code]
  Issue category: [cat]
  Occurrence count: [n]
  Confidence: [level]
  Last seen: [date]
  Matches gate(s): [stale | single_occurrence | low_confidence | superseded]

Action: keep | archive | edit text | show full record
```

Accept one of the four keywords. Behavior per choice:

- **keep** — no-op; advance to the next candidate. Acknowledge: `Kept: [first 60 chars of rule]...`
- **archive** — trigger the Step 2 backup if not already triggered; append a new entry to `corrections/archive/rules_archive.json` > `archived` array with this exact shape:
  ```json
  {
    "rule_id": "<deterministic id from rule fields — sha1(language + issue_category + rule)[:8]>",
    "reason": "pruned:<dominant_reason>",
    "archived_at": "<ISO 8601 UTC YYYY-MM-DDTHH:MM:SSZ>",
    "original_record": { ...the full rule object verbatim... }
  }
  ```
  Then mark all source entries in `corrections/corrections_log.json` > `corrections` whose `language + issue_category` match this rule AND whose `rule_extracted` is semantically equivalent for archival removal — when Step 9.4 rebuilds, those entries will be excluded. Implementation: stamp them with a top-level `_archived_at` field so the rebuild knows to skip them. Acknowledge: `Archived: [first 60 chars]... → corrections/archive/rules_archive.json (reason: pruned:<dominant_reason>)`.
- **edit text** — prompt: `New rule text:` and accept a single-line replacement. Update the rule's `rule` field in `rules_summary.json` and update the source `rule_extracted` in matching `corrections_log.json` entries. Increment nothing; do not change confidence. Acknowledge: `Edited: rule text updated.`
- **show full record** — print the full rule object as pretty-printed JSON, then re-prompt the action menu (do not advance to the next candidate).

**Stop condition:** continue until every candidate has received `keep`, `archive`, or `edit text` (excluding `show full record`, which loops). User can type `skip-rest` at any prompt to keep all remaining candidates and exit the phase.

### 9.3 — Empty session pruning still runs (per CONTEXT.md)

Even if Steps 0–8 produced zero writes (no batch input, all dismissed), Step 9 still scans and surfaces candidates. The user may use `/submit-feedback` purely as a maintenance call.

### 9.4 — Re-rebuild rules_summary.json (only if any archive or edit happened)

If Step 9.2 produced at least one `archive` or `edit text` action, run the Step 7 rebuild logic again (read `corrections/corrections_log.json` excluding entries marked `_archived_at`, deduplicate, write the new `rules_summary.json`). If Step 9.2 produced only `keep` actions, skip the rebuild.

Pruning phase complete:
- [N] candidates surfaced

- [A] archived (→ corrections/archive/rules_archive.json)
- [E] edited
- rules_summary.json: <rebuilt | unchanged>
```
````
